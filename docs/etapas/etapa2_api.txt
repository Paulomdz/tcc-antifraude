ETAPA 2 - CORREÇÕES DA API

Escopo
Correções da API e seus testes. Nenhum modelo, feature, split ou módulo de
orquestração foi alterado nesta tarefa; nenhum treinamento foi executado.

Arquivos
- src/api/main.py
  - Padronizados title, description e health check com o nome oficial informado
    pelo usuário: "Sistema Multiagente de IA para Detecção de Fraudes".
  - Mantido o import do módulo real da orquestração.
  - Adicionado o contador "erros" ao resultado do lote; cada falha de análise
    incrementa esse contador.
  - Isolada a gravação no histórico em try/except por transação, com log de
    exceção e continuação do processamento do lote.
  - Decisões fora do mapeamento permitido agora geram ValueError explícito e
    são contabilizadas como erro no lote.
  - Comentário TCC registra que D2 é aplicado na função de features: step % 24
    antes de hora_norm = hora / 23, no treino e na inferência.
  - Mantidos o 503 e texto exato de D7, o modo fast do lote sem chave, os
    endpoints de histórico sem chave e explicabilidade.top3 vazio.
- src/ferramentas/leitor_arquivo_lote.py
  - Leitor único de CSV/TXT, com separador validado pelo cabeçalho, colunas

    amostragem determinística e equivalência fast com/sem chave.
- docs/etapas/etapa2_api.txt
  - Este relatório de alterações e evidências.

Decisões
- D2: a API preserva o step recebido. A função compartilhada de features aplica
  o módulo 24 antes da normalização; limitar a entrada a 0..23 seria
  incompatível com steps do dataset.
- D7: sem GOOGLE_API_KEY, /analise_transacao mantém o 503 com
  {"detail": "Gemini não configurado. Defina GOOGLE_API_KEY no .env."};
  lote e histórico continuam disponíveis sem chave.
- D8: lote chama orchestrate_ml_only (fast). Production continua na análise
  individual; deep permanece somente função de orquestração.
- D13: o pacote neste repositório é src/orquestacao/. O import da API aponta
  para src/orquestacao/fluxo_multiagente.py.
- Serviço: usado o nome oficial escolhido pelo usuário, sem inventar uma nova
  marca.
- Lote: `LIMITE_LOTE = 500` é a única constante do limite; 501 itens resultam
  em 422 com a mensagem exata "Lote máximo de 500 transações.".
- Arquivo: `POST /analise_lote/arquivo` recebe CSV com vírgula ou TXT com
  ponto e vírgula, amostra com seed fixa 42 e aceita `quantidade` de 1 a 500
  (padrão 300). A resposta informa quantidade solicitada/usada, total do
  arquivo, seed e se o arquivo tinha menos linhas que a quantidade pedida.
- Configuração: `GET /config` informa disponibilidade booleana do LLM, modelo
  selecionado e limite, sem expor GOOGLE_API_KEY.
- Fast: `/analise_lote` e o upload chamam somente `orchestrate_ml_only` e
  retornam `llm_usado="NAO"`, com ou sem GOOGLE_API_KEY.

Limitações
- A suíte completa registrada acima foi executada após a correção de features
  da Etapa 1 e antes do contrato de upload; a validação posterior da API foi
  focada nos 22 testes da API. Nenhuma chamada ao Gemini foi executada.
- O D13 do prompt usa uma grafia divergente; o diretório real e o import
  validado pelo teste são src/orquestacao/.
- A busca textual por "fallback" mantém referências benignas no dashboard e
  comentário explicativo; nenhuma delas é fallback determinístico do juiz.
- Os testes validam a API usando um orquestrador controlado; a implementação de
  modelos/orquestração não foi modificada nem revalidada neste escopo.
- Treinamento não foi executado nesta correção de API; tempo e RAM pico por
  modelo não se aplicam a esta tarefa.
